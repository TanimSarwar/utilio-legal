Phase 1: Build Generation & Signing Keystore

✓

1.1 Verify Configuration Files (app.json & package.json)

Ensure your package name, version, and Expo build plugins are correctly declared.

In app.json, confirm the Android package name is uniquely set and version code is initialized to 1:

app.json
"android": {
  "package": "com.utilio.app",
  "versionCode": 1,
  "adaptiveIcon": {
    "foregroundImage": "./assets/adaptive-icon.png",
    "backgroundColor": "#6366F1"
  },
  "permissions": [
    "ACCESS_COARSE_LOCATION",
    "ACCESS_FINE_LOCATION",
    "CAMERA"
  ]
}
ℹ️ Note: Google Play requires an Android App Bundle (.aab) rather than a raw .apk for initial submissions.
✓

1.2 Generate Android Signing Keystore & Build Release AAB

Build your production .aab package using Expo Application Services (EAS) CLI.

Run the following commands in your project root terminal:

Terminal Command
# 1. Install EAS CLI globally if not already installed
npm install -g eas-cli

# 2. Login to your Expo account
eas login

# 3. Configure EAS Build (if eas.json is missing or updating)
eas build:configure

# 4. Trigger production Android App Bundle (.aab) build
eas build --platform android --profile production
⚠️ Critical Security Step: EAS automatically generates and stores your Android Keystore securely on Expo Cloud servers. You can back it up anytime using:
eas credentials -p android

Phase 2: Play Console Account & Merchant Payout Setup

✓

2.1 Register Google Play Developer Account

Create your official publisher presence on Google Play.

  1. Visit Google Play Console Signup.
  2. Pay the $25 USD one-time registration fee using a credit/debit card.
  3. Complete Identity Verification: Upload your government ID (Passport, Driving License, or National ID) and proof of address.
  4. Select account type: Personal or Organization (Organizations require a D-U-N-S Number).
✓

2.2 Activate Google Payments Merchant Account (For Tips & In-App Purchases)

Required if you wish to accept digital tips, subscriptions, or feature unlocks within the app.

  1. Inside Play Console, navigate to Setup > Merchant Account.
  2. Click Create Merchant Account and link your business/personal bank details.
  3. Fill in tax information (W-8BEN for non-US residents or W-9 for US developers).
  4. Google pays out automatically around the 15th of each month when earnings exceed $100.

Phase 3: Data Safety, Privacy Policy & Mandatory Declarations

✓

3.1 Submit App Privacy Policy Link

Link your live hosted Privacy Policy file.

Your workspace already includes a formatted privacy policy in utilio-legal-pages/PRIVACY_POLICY.html. Host it on GitHub Pages or your custom web server and enter the URL in Play Console:

Privacy Policy URL Example
https://yourusername.github.io/utilio-legal-pages/PRIVACY_POLICY.html
✓

3.2 Complete Data Safety Questionnaire

Mandatory declarations for permissions used by Utilio (Location, Camera, Storage, AdMob).

In Play Console under App Content > Data Safety, declare the following data collection:

Data Type Collected / Shared Purpose Ephemeral / Processed?
Location (Coarse/Fine) Collected (Not Shared) Weather forecasting, Qibla compass & prayer times Processed locally, not stored on server
Camera Not Collected QR & Barcode Scanning Processed in-memory only
Device ID & Ad Data Shared with AdMob Advertising & Analytics Required for personalized / contextual ads
✓

3.3 Target Audience & IARC Content Rating

Complete rating survey to get ESRB, PEGI, and Google Play ratings.

  • Target Audience: Select 13+ (Selecting under 13 triggers strict Families Policy requirements which restrict AdMob ad network compliance).
  • IARC Rating Survey: Fill out the questionnaire. Declare Utilio as a Utility/Productivity tool with NO violence, sexual content, user interaction features, or gambling. You will instantly receive PEGI 3 / ESRB Everyone ratings.

Phase 5: Google AdMob Ads Setup & app-ads.txt

✓

5.1 Link AdMob to Play Console & Configure Production Unit IDs

Switch from AdMob test IDs to production revenue ad units.

Your app.json is configured with react-native-google-mobile-ads. Confirm your production AdMob App ID is set:

app.json
"react-native-google-mobile-ads": {
  "android_app_id": "ca-app-pub-4109550681532851~3931127790"
}

In your React Native screens, replace test IDs with live Ad Unit IDs created in AdMob Console:

  • Banner Ad Unit: E.g., ca-app-pub-4109550681532851/xxxxxxxxx1
  • Interstitial Ad Unit: E.g., ca-app-pub-4109550681532851/xxxxxxxxx2
  • Rewarded Ad Unit: E.g., ca-app-pub-4109550681532851/xxxxxxxxx3
✓

5.2 Host app-ads.txt for Verified Ad Earnings

Mandatory for anti-fraud protection and maximum ad CPM rates.

Create a file named app-ads.txt in your hosted domain web root (e.g. inside utilio-legal-pages/app-ads.txt) with the following single line:

app-ads.txt
google.com, pub-4109550681532851, DIRECT, f08c47fec0942fa0
✅ Once published at https://yourdomain.com/app-ads.txt, enter https://yourdomain.com as the Website URL in your Google Play Console store listing. AdMob will crawl it within 24 hours and verify your publisher account!

Fastest method to collect tips without complex native billing integration.

React Native Code Snippet
import * as WebBrowser from 'expo-web-browser';
import { TouchableOpacity, Text } from 'react-native';

const handleTipPress = async () => {
  // Opens your Buy Me a Coffee or Stripe tipping link in an in-app browser overlay
  await WebBrowser.openBrowserAsync('https://buymeacoffee.com/yourhandle');
};

export const TipButton = () => (
  <TouchableOpacity onPress={handleTipPress} style={{ padding: 14, backgroundColor: '#6366F1', borderRadius: 12 }}>

Phase 7: Mandatory 20 Testers Closed Testing & Review

✓

7.1 Master the "20 Testers for 14 Days" Play Store Rule

Mandatory requirement for personal developer accounts created after Nov 2023.

⚠️ Google Policy Requirement: Before applying for Production release access, you MUST recruit at least 20 testers who must remain opted into your Closed Test track continuously for 14 consecutive days.
  1. In Play Console, go to Testing > Closed testing.
  2. Create a test track, upload your .aab file built in Phase 1.
  3. Create a Google Group or gather email addresses of 20+ friends, colleagues, or testing community members (e.g. Reddit r/AndroidGroupTesting or Google Play Testing groups).
  4. Add their emails to the tester list and share the opt-in web link.
  5. Ensure all 20 testers click "Accept Invitation" and download/open Utilio on their Android phones.
  6. Maintain active testing status for 14 days without deleting the track.
  7. After 14 days, click Apply for Production Access and answer Google's feedback questionnaire.
✓

7.2 Submit to Production Review

Final submission step once Production Access is granted.

  • Go to Production track > Create new release.
  • Select your tested .aab bundle.
  • Write Release Notes (e.g., "Initial launch of Utilio - All-in-one utility app").
  • Click Save and Send for Review. Review typically takes between 1 to 7 business days.

Phase 8: Publishing App Updates & Maintenance

✓

8.1 How to Release App Updates

Workflow for releasing new features or bug fixes to existing users.

  1. In app.json, increment versionCode by +1 (e.g., from 1 to 2) and update version string (e.g., 1.0.1).
  2. Run eas build --platform android --profile production.
  3. Upload new .aab bundle in Play Console under Production > Create release.
